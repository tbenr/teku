# State diff storage (experimental)

Status: phase 1 (non-archive nodes) implemented behind a hidden flag; soak-tested
on mainnet and on sepolia (Gloas). Living document, last updated 2026-10-23.

Design: [docs/superpowers/specs/2026-10-22-state-diff-dag-design.md](superpowers/specs/2026-10-22-state-diff-dag-design.md).
Every non-obvious decision and all measurements:
[docs/superpowers/plans/2026-10-22-state-diff-dag-decisions-log.md](superpowers/plans/2026-10-22-state-diff-dag-decisions-log.md).

## What it does

Today Teku rewrites the full beacon state (~300 MB on mainnet) on every
finalization and stores another full state every second epoch per fork branch.
With state diff storage, epoch-boundary states are stored as a DAG of small
tree-based diffs keyed by checkpoint-block root. Finalization becomes a pointer
move, the finalized anchor and hot epoch states are reconstructed from a
snapshot plus a bounded chain of diffs, and old nodes are pruned as finality
advances. Changed validator supernodes are stored once, content-addressed, and
reference-counted. The same store is the foundation for an archive node
(phase 2) and for offloading exited validators from memory (phase 3).

## How to run it

```bash
teku --network=mainnet --data-storage-mode=minimal --Xdata-storage-state-diffs
```

- Works on RocksDB and LevelDB V6 databases (`V6`, `LEVELDB2`, `ROCKSDB_TREE`,
  `LEVELDB_TREE`); V4/V5 databases are rejected at startup.
- An existing database is migrated in place on first start: a snapshot node is
  written from the stored finalized state and `LATEST_FINALIZED_STATE` is
  deleted, in one transaction. A fresh database writes its anchor as a snapshot.
- The mode is sticky: a marker in the database keeps it on even if the flag is
  removed later. There is no downgrade path; try it on a copy of your data
  directory first.
- `--Xhot-state-persistence-frequency` and `--data-storage-archive-frequency`
  are ignored while it is on (a WARN says so). Archive mode still works but
  keeps its legacy finalized-state storage until phase 2.
- Only the storage changes; block import, fork choice and the APIs are untouched.
  Mid-epoch states are regenerated by replaying at most one epoch of blocks from
  the nearest node, as before.

Offline tools (database must be stopped):

```bash
teku debug-tools db verify-state-diffs --network=mainnet --data-path=<dir>
```

```bash
teku debug-tools rocksdb usage --network=mainnet --data-path=<dir> --filter=STATE_
```

`verify-state-diffs` recounts supernode references, checks every node's parent,
reconstructs the finalized anchor and exits 1 on any problem. `rocksdb usage`
prints RocksDB keys, total, SST, blob and estimated live bytes per column family;
`--filter` keeps the columns whose name contains it, ignoring case.

Metrics (Prometheus, `storage_state_diff_*`): `nodes_total{state}`,
`snapshots_total{reason}`, `node_bytes{level}`, `section_bytes_total{section}`,
`write_seconds`, `write_phase_seconds_total{phase}`, `reconstruct_seconds`,
`reconstruct_chain_length`, `base_cache_total{result}`,
`verification_failures_total`; plus `storage_store_state_diff_nodes_skipped_total`.

## Measured so far

Soak on copies of real MINIMAL-mode databases with the stub execution engine
(the same way those nodes were already run), 7 hours on the final build after
the migration path, with `verify-state-diffs` clean on both.

| | Mainnet (Fulu, ~2M registry entries) | Sepolia (Gloas) |
|---|---|---|
| Bytes written per epoch, raw | ~4.3 MB diff + changed supernodes (8 × 31 KB on a sampled epoch) | ~430 KB |
| Bytes written per epoch, on disk | ~3 MB + supernodes | ~430 KB |
| Previously written per epoch | ~300 MB finalized state + ~150 MB hot state | |
| Periodic snapshot (every 256 epochs) | 20.9 MB raw | 3.4 MB |
| Steady-state state storage on disk | ~255 MB (was ~900 MB) | ~6 MB |
| Node write on the storage thread | ~48 ms (walk ~43 ms, encode ~4 ms, store <1 ms) | ~9 ms |
| Finalized anchor reconstruction at startup | 22-link chain in 3.1 s (offline) | 11-link chain in 0.13 s |
| Extra live heap vs stock node (A/B, same build) | +0.7 GB | |
| Errors, verification failures, skipped nodes in 7 h | 0 / 0 / 1 (handled) | 0 / 0 / 0 |

So on a mainnet prune node, bytes written for states drop by roughly 30 to 50
times, and the on-disk footprint of state storage by about 3.5 times, for about
0.7 GB more heap.

## Known limits and open decisions

1. **Delta section compression** (decisions log 42). The per-epoch payload is
   dominated by balance and inactivity-score deltas (~4 MB raw). RocksDB LZ4
   gives only ~2.8x on them and Teku disables compression on the bottom-most
   level, so long-lived nodes end up uncompressed. Application-level zstd or
   gzip on that section, under payload version 2, should bring a mainnet epoch
   node well under 1 MB on disk.
2. **Per-validator supernode patches** (decisions log 41). Changed supernodes
   are stored whole (31 KB); patching only the changed 121-byte validators
   mainly helps coarse nodes and refcount churn.
3. **Cold base-cache reconstruction on the live node** took 14.5 s for the first
   node after a restart, against 3.1 s offline; needs profiling before the flag
   can default on.
4. The per-level base cache holds up to 3 trees per level; `baseCacheLevels`
   exists in `StateDiffDagConfig` but is not yet exposed on the CLI.
5. Retention after a long non-finality period decodes every intermediate node's
   payload in one transaction; store the supernode hash list in the record
   header or batch deletions if this matters.

## Next steps

- Phase 2, first slice: a retention window. Keep the last W epochs of states
  (reusing `--Xdata-storage-archive-finalized-states-retained`) plus the
  reconstruction chain of the oldest one; history starts at the switch or the
  checkpoint anchor, no genesis backfill. Roughly 0.7 to 1.3 GB per day of
  mainnet history at today's node sizes, half that once deltas are compressed.
- Phase 2, archive node: configurable coarse levels above 256 epochs, historical
  reads through the DAG (one snapshot plus at most 38 diffs, however old the
  epoch), `--reconstruct-historic-states` integration (spec 5.11).
- Phase 2, reconstruction anchor: let a fresh node supply an older finalized
  state so backfill and reconstruction start there instead of genesis; the
  state is verified against the block's state root once the block backfill
  reaches it, and an anchor older than the peers' required serving window only
  warns and keeps retrying.
- Phase 3, frozen exited-validator supernodes: keep only the hash of supernodes
  whose validators are all withdrawn, load on demand from the supernode column,
  skip them in per-epoch iteration (spec section 9).
- Optional tier 2, per-block diffs for hot states: needs a sparse byte-patch
  section for participation flags first; worth it only for read-heavy hot-state
  workloads (see the decisions log).
- Flip the default once items 1 and 3 above are done and a multi-week soak
  including reorgs at epoch boundaries is clean.
