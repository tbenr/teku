# State diff storage (experimental)

Status: implemented behind a hidden flag, for prune nodes and for archive nodes
(finalized states in the DAG, optional retention window), with node payload
version 2. Soaked on mainnet (local clones, and an archive and a minimal box on
AWS since 2026-10-29); the first build was also soaked on sepolia (Gloas), and
the Fulu to Gloas fork crossing was verified on a kurtosis devnet. Living
document, last updated 2026-11-16.

Design: [docs/superpowers/specs/2026-10-22-state-diff-dag-design.md](superpowers/specs/2026-10-22-state-diff-dag-design.md).
Every non-obvious decision and all measurements:
[docs/superpowers/plans/2026-10-22-state-diff-dag-decisions-log.md](superpowers/plans/2026-10-22-state-diff-dag-decisions-log.md).

## What it does

Today Teku rewrites the full beacon state (~300 MB on mainnet) on every
finalization and stores another full state every second epoch per fork branch.
With state diff storage, epoch-boundary states are stored as a DAG of small
tree-based diffs keyed by checkpoint-block root. Finalization becomes a pointer
move, the finalized anchor and hot epoch states are reconstructed from a
snapshot plus a bounded chain of diffs, and old nodes are pruned as finality
advances. Snapshots store the validator supernodes once, content-addressed and
reference-counted; a diff patches the few changed validators of a supernode
inline instead of storing a new 31 KB copy. The same store is the foundation for an archive node
(phase 2); offloading exited validators from memory (phase 3) was attempted and
measured on 2026-10-29 and is not pursued in that form (design section 9).

## How to run it

```bash
teku --network=mainnet --data-storage-mode=minimal --Xdata-storage-state-diffs
```

- Works on RocksDB and LevelDB V6 databases (`V6`, `LEVELDB2`, `ROCKSDB_TREE`,
  `LEVELDB_TREE`); V4/V5 databases are rejected at startup.
- An existing database is migrated in place on first start: a snapshot node is
  written from the stored finalized state and `LATEST_FINALIZED_STATE` is
  deleted, in one transaction. A fresh database writes its anchor as a snapshot.
- The mode is sticky: a marker in the database keeps it on even if the flag is
  removed later. There is no downgrade path; try it on a copy of your data
  directory first.
- Databases written in state diff mode by a branch build from before 2026-11-14
  are not readable as they are: the payload format, two column IDs and the
  variable ID of the mode marker changed since (decisions log 73, 76, 79). Use
  a fresh data directory or, for a database already on payload version 2, the
  one-off migrations of entries 76, 79 and 82. A marker other than 2 fails at
  open as an unknown state diff storage format.
- `--Xhot-state-persistence-frequency` and `--data-storage-archive-frequency`
  are ignored while it is on (a WARN says so).
- Only the storage changes; block import, fork choice and the APIs are untouched.
  Mid-epoch states are regenerated by replaying at most one epoch of blocks from
  the nearest node, as before.

Modes:

| `--data-storage-mode` | `--Xdata-storage-archive-finalized-states-retained` | Finalized states kept in the DAG | Served by `/eth/v2/debug/beacon/states/{slot}` and other historical reads |
|---|---|---|---|
| `minimal` / `prune` | not allowed | the finalized anchor's reconstruction chain only | no (as today) |
| `archive` | 0 (default) | every finalized checkpoint-block node since the switch or the checkpoint-sync anchor | every epoch from the switch on |
| `archive` | `W` slots (> 0) | the nodes of the last `W / slots_per_epoch` epochs before the finalized checkpoint, plus the reconstruction chain of the oldest one | every epoch of the window |

```bash
teku --network=mainnet --data-storage-mode=archive --Xdata-storage-state-diffs \
  --Xdata-storage-archive-finalized-states-retained=230400   # 7200 epochs, about 32 days
```

- In archive mode, finalized states are read from the DAG: the node of the
  epoch's checkpoint block, then finalized blocks are replayed to the requested
  slot (at most one epoch). Nothing is written to the legacy finalized state
  columns any more; the state-root index is still written. History from before
  the switch is not served (a database switched in place keeps its legacy
  finalized states on disk, unused and not pruned), and there is no genesis
  backfill: `--reconstruct-historic-states` is not integrated yet, and is
  rejected at startup with `--Xdata-storage-state-diffs` (not detected when
  the flag was removed from a database already in state diff mode).
- A read in the window falls back to the latest earlier checkpoint block's node
  when an epoch's node was skipped; at the window start, that is the oldest
  retained node, just below the start.
- The legacy state pruner is not started; the window is applied at each
  finalization. Lowering the window, or setting one on a database that kept
  everything, deletes the backlog at most 256 epochs per finalization (INFO
  log). Raising it does not bring deleted history back.
- The existing option checks still apply: the retained slots need archive mode
  and must be at least `--data-storage-archive-frequency` (default 2048, also
  checked although the frequency is otherwise ignored), and they cannot be
  combined with `--reconstruct-historic-states`.

Offline tools (database must be stopped):

```bash
teku debug-tools db verify-state-diffs --network=mainnet --data-path=<dir>
```

```bash
teku debug-tools rocksdb usage --network=mainnet --data-path=<dir> --filter=STATE_
```

`verify-state-diffs` recounts supernode references, checks that every referenced
supernode's content hashes to its key (reconstruction trusts it to), checks
every node's parent, reconstructs the finalized anchor and exits 1 on any
problem. `rocksdb usage`
prints RocksDB keys, total, SST, blob and estimated live bytes per column family;
`--filter` keeps the columns whose name contains it, ignoring case.

Metrics (Prometheus, `storage_state_diff_*`): `nodes_total{state}`,
`snapshots_total{reason}`, `node_bytes{level}`, `section_bytes_total{section}`
and `section_entries_total{section}` (the bytes each section takes in the
payload, counts, gIndexes and lengths included, so the sections other than
`deltas` sum to the payloads less one version byte each; `deltas` counts the
raw delta bytes and `deltas_compressed` the delta section as stored, so their
ratio is the delta compression ratio), `write_seconds`,
`write_phase_seconds_total{phase}`, `reconstruct_seconds`,
`reconstruct_chain_length`, `base_cache_total{result}`,
`verification_failures_total`, `window_start_epoch` (archive only); plus
`storage_store_state_diff_nodes_skipped_total`.

## Measured so far

First soak (payload version 1, 2026-10-22 and 23): copies of real MINIMAL-mode
databases with the stub execution engine, 7 hours on the final build after the
migration path, with `verify-state-diffs` clean on both.

| | Mainnet (Fulu, ~2M registry entries) | Sepolia (Gloas) |
|---|---|---|
| Bytes written per epoch, raw | ~4.3 MB diff + changed supernodes (8 × 31 KB on a sampled epoch) | ~430 KB |
| Bytes written per epoch, on disk | ~3 MB + supernodes | ~430 KB |
| Previously written per epoch | ~300 MB finalized state + ~150 MB hot state | |
| Periodic snapshot (every 256 epochs) | 20.9 MB raw | 3.4 MB |
| Steady-state state storage on disk | ~255 MB (was ~900 MB) | ~6 MB |
| Node write on the storage thread | ~48 ms (walk ~43 ms, encode ~4 ms, store <1 ms) | ~9 ms |
| Finalized anchor reconstruction at startup | 22-link chain in 3.1 s (offline, before the applier wave); 12-link chain in ~1.2 s on the live node after it | 11-link chain in 0.13 s |
| Extra live heap vs stock node (A/B, same build) | +0.7 GB | |
| Errors, verification failures, skipped nodes in 7 h | 0 / 0 / 1 (handled) | 0 / 0 / 0 |

So on a mainnet prune node, bytes written for states drop by roughly 30 to 50
times, and the on-disk footprint of state storage by about 3.5 times, for about
0.7 GB more heap.

Since then, on mainnet:

- **Payload version 2** (decisions log 75; local archive clone, 2,160 node
  writes): the compressed delta section is 19.5 times smaller than raw and
  supernode patches take 6.4 KB per node. A node costs about 1.8 MiB per epoch
  on disk, about 0.4 GiB per day of history, most of it the participation
  leaves, which are stored uncompressed. Node writes take 70 ms on average
  while syncing (walk 59 ms, encode 9.6 ms), and a 17-link anchor chain
  rebuilds in 1.23 s.
- **Restart** (decisions log 49, 50): the anchor reconstructed at startup seeds
  the base cache and every reconstruction stops at the first cached node of
  its chain. After a restart at a mid-period anchor the startup reconstruction
  walked 12 links in about 1.2 s and the first node write rebuilt its parent
  in 1 link under 0.25 s, where it took 14.5 s before.
- **Archive retention window** (payload version 1, decisions log 61):
  historical reads take 1.6-3 s at a checkpoint slot, plus block replay inside
  the epoch.
- **AWS boxes** (decisions log 78, 82): the minimal box wrote 3,452 nodes in
  15 days at head with no verification failure and no storage error. On the
  archive box the nodes take 6.7 GiB next to 770 GiB of blocks, and an offline
  verify of 5,046 nodes is clean in 79 s. Full GCs come with syncing and stop
  at head.

## Known limits

- No downgrade, and an archive database serves no history from before the
  switch (see How to run it).
- Archive databases use the prune levels: an old epoch costs a snapshot plus
  up to 21 diffs, and a snapshot of about 20 MB is written every 256 epochs.
- The base cache holds 3 trees at the finest level and 1 at each coarser
  level and is not configurable (decisions log 49). The A/B of the first soak
  measured 0.7 GB more live heap than a stock node.
- Participation leaves are not compressed by the application and are most of
  a node's bytes (decisions log 75).
- Retention after a long non-finality period decodes every intermediate
  node's payload in one transaction. Measured warm at about 2 ms per node;
  reading the nodes back from disk is the larger part (decisions log 89, 93).
- In archive mode the first finalization after a long non-finality period
  reconstructs every finalized checkpoint node of the stall, in one storage
  update, only to fill the state root index: 0.7 s each measured locally, 2.3 s
  at the median on the archive box (decisions log 93).

## Next steps

- Soak longer: the archive over weeks, a longer retention window, and reorgs
  at epoch boundaries; flip the default after a clean multi-week run.
- Payload version 3: compress the leaves section like the deltas (decisions
  log 75). Gloas adds `ptc_window`, about 0.4 MB per epoch.
- Archive: configurable coarse levels above 256 epochs, and the
  `--reconstruct-historic-states` integration (spec 5.11).
- Reconstruction anchor: let a fresh node supply an older finalized state so
  backfill and reconstruction start there instead of genesis; the state is
  verified against the block's state root once the block backfill reaches it,
  and an anchor older than the peers' required serving window only warns and
  keeps retrying.
- Optional tier 2, per-block diffs for hot states: needs a sparse byte-patch
  section for participation flags first; worth it only for read-heavy
  hot-state workloads (see the decisions log).
- Not pursued in its attempted form: frozen exited-validator supernodes
  (design section 9, decisions log 77).
- Parked until the feature is in master: the open design calls and the
  deferred optimisations, with their measurements, are in decisions log 86.
